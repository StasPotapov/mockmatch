# Альтернативы

[English](alternatives.md)

Что существовало в октябре 2026 года, когда начался mockmatch, и почему mockmatch всё равно написан. Факты ниже взяты
со страниц проектов и из каталогов. Ни один из этих инструментов не ставили и не замеряли.

## Управление браузером для агентов

| Инструмент | Что это | Почему не только он |
|---|---|---|
| [agent-browser](https://agent-browser.dev/) (Vercel Labs) | CLI; `snapshot` отдаёт дерево доступности со ссылками `@e1`, по данным авторов ~200–400 токенов на снимок | только управление, сверки с дизайном нет |
| [Playwright CLI](https://www.webfuse.com/blog/playwright-mcp-vs-playwright-cli) | пишет снимки и скриншоты в файлы, а не в контекст; приводят ~27k против ~114k токенов на задачу у Playwright MCP (откуда число, неясно) | только управление |
| Playwright MCP, chrome-devtools-mcp | MCP-серверы; снимки идут прямо в контекст | та трата токенов, которой mockmatch избегает |
| [CDPM](https://github.com/IGELHARINE/CDPM) (IGELHARINE, npm `cdpm-mcp`) | MCP-сервер; до 30 пронумерованных Chrome со входом в аккаунты, работает по чистому CDP. Браузеры общие для многих сессий Claude Code и субагентов, агенты обмениваются сообщениями | общие браузеры для многих агентов, сверки с дизайном нет. Этот инструмент сначала тоже назывался cdpm и стал mockmatch, чтобы имена не совпадали |

mockmatch берёт ту же идею (текст со ссылками, результаты в файлах). К ней он добавляет отчёт о том, что изменилось
после каждого клика, `--expect` и сверку с дизайном.

## Дизайн против реализации

| Инструмент | Подход | Чего не хватает здесь |
|---|---|---|
| [figma-map](https://pkg.go.dev/github.com/kirillbaranov/figma-map) | `verify reconcile` сравнивает вычисленные стили DOM со значениями из Figma поэлементно, «есть / должно быть»; `verify pixeldiff` ищет худший участок | самая близкая идея; дизайн читает только из Figma |
| [mcp-perfectpixel](https://glama.ai/mcp/servers/x8pnhgknrb) | детерминированный скриншот URL против PNG дизайна; участки с важностью, привязанные к элементам DOM | только пиксели; дизайн должен быть PNG |
| [imugi](https://lobehub.com/mcp/m00n7682-imugi) | цикл: скриншот → SSIM + pixelmatch + Claude Vision → правка, пока не будет 95% | шлёт картинки модели на каждом шаге |
| UI Diff, design-compare, Visual Page Comparison (каталоги скиллов) | полные скриншоты в модель | самый дорогой способ |

Дизайн живёт в Claude Design, а файл Claude Design — это HTML. Поэтому обе стороны можно сравнить как DOM
с вычисленными стилями, без Figma и без модели в цикле. Пиксели и дешёвый субагент закрывают только то,
что стили показать не могут. Ни один найденный инструмент не делал этого для Claude Design или простых
HTML-макетов.
